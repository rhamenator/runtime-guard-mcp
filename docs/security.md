# Security model

The server is advisory. A model may ignore a result and use another tool. For hard containment, configure the agent host to make this server the route for relevant operations and apply OS sandbox or policy controls.

The path tool checks a proposed path after `Path.resolve`; it rejects traversal beyond configured roots and sensitive names. It cannot prevent time-of-check/time-of-use races or detect all sensitive filenames. Do not treat its verdict as a capability token.

The command tool never executes. Pattern and `shlex` checks can miss shell language constructs, aliases, environment expansions, and platform-specific syntax. Unknown and compound commands require review. Any `SAFE` result means only that the current heuristics found no listed risk.

Budget counts are caller-reported. The server cannot independently know model token usage or actions made outside it. Each caller's metric history is capped at 8192 reservation records per metric, and fingerprint history is capped at 4096 records process-wide. A reservation that would exceed either state cap returns `BLOCKED` without partially consuming another metric; records are released when their sliding windows expire. High-frequency legitimate callers can hit these state caps before the numeric budget. In memory windows reset on restart, and multiple replicas do not share limits. The optional SQLite database stores only redacted decision metadata in a SHA-256 hash chain. The server verifies the chain on startup and refuses a tampered database; it checks the latest row before each append. If an audit write or this check fails, the tool returns `BLOCKED` / `AUDIT_UNAVAILABLE` without its computed result. Policy state may already have changed before that audit failure, so retry only after repair. `AuditLog.verify_integrity()` detects altered and deleted interior rows; it cannot prove the last row was not deleted without an external anchor, and a full interior check is not performed on every append. Configure filesystem permissions and retention externally.

Masking is best effort. It recognizes several credential forms, email addresses, and US Social Security number shapes, but cannot identify every secret or private identifier. Raw secrets are not logged or persisted; the in-memory lookup stores hashes to keep placeholders stable. The process allows at most 128 unfinished streams and 4096 distinct secret mappings per caller; exceeding either limit returns a `BLOCKED` result with no text. A stream blocked while masking must be ended with `final=true` before its identifier can be reused; the blocked stream is discarded without emitting its tail. Buffered raw stream tails are removed when a stream finishes, and clients should always finish abandoned streams. These bounds may deny further masking until streams finish or the process restarts. The process memory can still contain transient sensitive data, so run it under the user's account and restrict access.

HTTP defaults to loopback. Exposing it beyond loopback requires a bearer token and TLS proxy. The HTTP server rejects duplicate Host, Origin, Authorization, Content-Length, and Content-Type headers, malformed Host or Origin authorities, unsupported transfer encoding, and non-JSON POST media types before dispatch. Origins must use HTTP or HTTPS. It does not interpret chunked request bodies. The server limits active handlers to 32 and returns 503 when all slots are occupied. It closes sockets after five seconds of inactivity or five seconds total per connection, including incomplete headers or bodies. The absolute deadline prevents a peer from holding a handler indefinitely by slowly dripping bytes, but can disconnect legitimate slow uploads. These are process-level resource bounds, not caller quotas; a client can still consume all slots for short intervals, and the listen backlog and upstream proxy need their own limits. For production, add per-client identity, stronger HTTP transport compatibility checks, and a sandbox around any future active executor.

Both stdio and HTTP decode requests as UTF-8 JSON. Duplicate object keys, non-finite constants or overflowed floating-point numbers, invalid UTF-8, and nesting deeper than 64 levels return a JSON-RPC `-32700` parse error before dispatch. The depth scan ignores brackets inside quoted strings and runs before the JSON decoder constructs nested containers. This avoids ambiguous parsing and bounds nesting amplification; the one-megabyte frame cap still permits sizable flat objects, so it is not a complete memory-use limit. A malformed frame does not poison the next request.

Stdio reads at most 1 MiB plus one byte before deciding whether a line is oversized, then drains the rest in 64 KiB pieces and returns one controlled error. It does not parse the remainder as additional requests. The client still controls how fast it writes; host-level process limits remain useful for a compromised local client.
